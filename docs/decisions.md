# Принятые решения

## React + Vite вместо Next.js (pr-001)

Приложение — личный кабинет за авторизацией: его страницы не нужно индексировать поисковикам, поэтому серверный рендеринг Next.js ничего не даёт. Клиентское приложение на Vite проще превратить в PWA с офлайн-режимом, в нём удобнее запускать ONNX-модель в Web Worker и открывать его как Telegram WebApp. Собранная статика раздаётся любым веб-сервером.

## Vitest вместо Jest (pr-001)

Vitest использует конфигурацию Vite (плагины, TypeScript без отдельного транспайлера), а его API совместим с Jest — тесты с Testing Library пишутся так же. Юнит-тесты UI-кита в pr-018 тоже будут на Vitest.

## Tailwind CSS 4 (pr-001)

Подключён через плагин `@tailwindcss/vite`, отдельные конфиги PostCSS и Tailwind не нужны.

## CI с первого PR (pr-001)

В плане фронтенда нет отдельной задачи на CI, поэтому GitHub Actions добавлен сразу: на каждый PR и push в `main` выполняются проверка типов, тесты и сборка.

## ESLint, Prettier и Stylelint (pr-002)

- ESLint 9 с плоским конфигом: базовые правила, typescript-eslint с проверками на основе типов, правила хуков React, react-refresh для Vite и jsx-a11y для доступности. Версия 9, а не 10: `eslint-plugin-jsx-a11y` пока поддерживает только ESLint до 9-й версии, а проверять доступность нужно с самого начала (в плане есть pr-094).
- Prettier отвечает за форматирование: без точек с запятой, одинарные кавычки. Плагин `prettier-plugin-tailwindcss` сортирует классы Tailwind в рекомендованном порядке. Правила ESLint, которые конфликтуют с Prettier, отключены через `eslint-config-prettier`.
- Stylelint со стандартным набором правил. Директивы Tailwind 4 (`@theme`, `@utility`, `@apply` и т. д.) разрешены, импорт — строкой, как в документации Tailwind.
- Все проверки выполняются в CI.

## Atomic Design и алиас `@/` (pr-003)

- Компоненты разложены по уровням `atoms` → `molecules` → `organisms` → `templates`; страницы лежат в `src/pages`, корень приложения — в `src/app`. Правило зависимостей: компонент использует только компоненты своего или более низкого уровня. Описание уровней — в `src/components/README.md`.
- Один компонент — один файл, тест лежит рядом (`Logo.tsx` и `Logo.test.tsx`). Без barrel-файлов `index.ts`: они мешают горячей перезагрузке и разбиению бандла.
- Алиас `@/` указывает на `src/` и настроен в `tsconfig.app.json` и `vite.config.ts`, поэтому импорты не зависят от глубины вложенности: `@/components/atoms/Logo`.
- Именованные экспорты вместо экспортов по умолчанию: имя компонента одинаковое во всех файлах, и его проще найти поиском.

## Zustand вместо Redux Toolkit (pr-004)

Данные с сервера (участки, диагнозы, прогнозы) будет хранить и кэшировать TanStack Query (pr-005). Глобального клиентского состояния остаётся немного: интерфейс, сессия пользователя, выбранные слои карты. Для этого достаточно Zustand: хранилище — это один хук без провайдеров, экшенов и редьюсеров, а компонент перерисовывается только при изменении выбранной части состояния. Хранилища лежат в `src/store`, по одному файлу на область.

## Axios + TanStack Query (pr-005)

- Axios — HTTP-клиент с общими настройками (`src/api/client.ts`): базовый адрес из `VITE_API_URL`, таймаут 15 с.
- Interceptor запроса добавляет заголовок `Authorization: Bearer …`, если есть токен. Откуда брать токен, решает модуль авторизации (pr-014): он передаст функцию в `setTokenProvider`, и клиент не будет зависеть от способа хранения токена.
- Interceptor ответа превращает любые сбои в `ApiError` со статусом и понятным текстом: из поля `detail` ответа FastAPI или «Сервер недоступен», если ответа нет. Интерфейсу не нужно разбирать ошибки Axios.
- TanStack Query хранит и кэширует данные с сервера: данные считаются свежими 30 с. При ошибках 4xx запрос не повторяется — ответ не изменится, — при сбоях сети и 5xx делаются ещё две попытки.
- В режиме разработки Vite проксирует `/api` на `http://127.0.0.1:8000`, поэтому фронтенд и бэкенд работают вместе без настройки CORS.
- В тестах запросы перехватывает MSW на уровне сети. Код приложения не знает о моках, а неожиданный запрос роняет тест (`onUnhandledRequest: 'error'`).

## Базовый UI-кит (pr-006)

- Компоненты написаны на Tailwind без сторонней библиотеки компонентов: внешний вид полностью свой, а в бандл не попадает лишний код. Варианты (`primary`, `secondary`, `ghost`, `danger`) и размеры кнопки описаны обычными объектами классов, без class-variance-authority: вариантов мало.
- Классы склеивает `cn` (`clsx` + `tailwind-merge`). `tailwind-merge` убирает конфликтующие классы, поэтому `className`, переданный снаружи, перекрывает стиль по умолчанию, а не зависит от порядка классов в CSS.
- Атомы принимают все атрибуты своего HTML-элемента и `ref` (в React 19 это обычный проп, `forwardRef` не нужен), поэтому подключаются к React Hook Form (pr-011) без обёрток.
- Кнопка по умолчанию `type="button"`: случайная кнопка внутри формы не отправит её. Во время загрузки кнопка заблокирована, показывает индикатор и помечена `aria-busy`.
- `Field` — подпись, подсказка и ошибка вокруг любого поля. Он сам создаёт `id` через `useId` и передаёт полю `aria-describedby` и `aria-invalid`, так что экранные дикторы читают подсказку и ошибку, а стиль ошибки поле берёт из `aria-invalid`. Само поле передаётся функцией: одна обёртка подходит для `Input`, `Textarea` и будущих выпадающих списков (pr-008).
- Включён `strict` в `tsconfig`: строгая типизация обязательна по правилам проекта, а в pr-001 её не включили. Код уже ей соответствовал, ошибок не появилось.

## Карточки, модальные окна, скелетоны (pr-007)

- Модальное окно построено на нативном `<dialog>` с `showModal()`. Браузер сам удерживает фокус внутри окна, делает остальную страницу недоступной (`inert`), закрывает окно по Esc и возвращает фокус на кнопку, которая его открыла. Библиотека для фокус-ловушки не нужна. Окно управляется пропом `open`; закрытие по Esc, кнопкой «Закрыть» или кликом по фону вызывает `onClose`. Прокрутка страницы под открытым окном отключена в CSS (`html:has(dialog[open])`).
- В jsdom у `<dialog>` нет `showModal()` и `close()`, поэтому тесты подставляют минимальную замену в `src/test/setup.ts`.
- `Card` — секция с необязательными заголовком, описанием и действиями. Если заголовок задан, секция подписана им (`aria-labelledby`) и видна дикторам как отдельная область.
- Скелетоны скрыты от экранных дикторов (`aria-hidden`), а о загрузке сообщает контейнер с `role="status"` и скрытым текстом «Загрузка…»: иначе диктор прочитал бы набор пустых блоков.
