# Принятые решения

## React + Vite вместо Next.js (pr-001)

Приложение — личный кабинет за авторизацией: его страницы не нужно индексировать поисковикам, поэтому серверный рендеринг Next.js ничего не даёт. Клиентское приложение на Vite проще превратить в PWA с офлайн-режимом, в нём удобнее запускать ONNX-модель в Web Worker и открывать его как Telegram WebApp. Собранная статика раздаётся любым веб-сервером.

## Vitest вместо Jest (pr-001)

Vitest использует конфигурацию Vite (плагины, TypeScript без отдельного транспайлера), а его API совместим с Jest — тесты с Testing Library пишутся так же. Юнит-тесты UI-кита в pr-018 тоже будут на Vitest.

## Tailwind CSS 4 (pr-001)

Подключён через плагин `@tailwindcss/vite`, отдельные конфиги PostCSS и Tailwind не нужны.

## CI с первого PR (pr-001)

В плане фронтенда нет отдельной задачи на CI, поэтому GitHub Actions добавлен сразу: на каждый PR и push в `main` выполняются проверка типов, тесты и сборка.

## ESLint, Prettier и Stylelint (pr-002)

- ESLint 9 с плоским конфигом: базовые правила, typescript-eslint с проверками на основе типов, правила хуков React, react-refresh для Vite и jsx-a11y для доступности. Версия 9, а не 10: `eslint-plugin-jsx-a11y` пока поддерживает только ESLint до 9-й версии, а проверять доступность нужно с самого начала (в плане есть pr-094).
- Prettier отвечает за форматирование: без точек с запятой, одинарные кавычки. Плагин `prettier-plugin-tailwindcss` сортирует классы Tailwind в рекомендованном порядке. Правила ESLint, которые конфликтуют с Prettier, отключены через `eslint-config-prettier`.
- Stylelint со стандартным набором правил. Директивы Tailwind 4 (`@theme`, `@utility`, `@apply` и т. д.) разрешены, импорт — строкой, как в документации Tailwind.
- Все проверки выполняются в CI.

## Atomic Design и алиас `@/` (pr-003)

- Компоненты разложены по уровням `atoms` → `molecules` → `organisms` → `templates`; страницы лежат в `src/pages`, корень приложения — в `src/app`. Правило зависимостей: компонент использует только компоненты своего или более низкого уровня. Описание уровней — в `src/components/README.md`.
- Один компонент — один файл, тест лежит рядом (`Logo.tsx` и `Logo.test.tsx`). Без barrel-файлов `index.ts`: они мешают горячей перезагрузке и разбиению бандла.
- Алиас `@/` указывает на `src/` и настроен в `tsconfig.app.json` и `vite.config.ts`, поэтому импорты не зависят от глубины вложенности: `@/components/atoms/Logo`.
- Именованные экспорты вместо экспортов по умолчанию: имя компонента одинаковое во всех файлах, и его проще найти поиском.
